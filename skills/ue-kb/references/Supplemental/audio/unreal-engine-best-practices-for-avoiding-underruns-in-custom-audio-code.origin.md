### 概览

*文章由 [Anna L.](https://dev.epicgames.com/community/profile/Ob2/lantz.anna) 撰写* 有时，在虚幻引擎中添加自定义 DSP 代码或更改音频功能时，用户会在音频中遇到意外的“嗡嗡声”或“断断续续”的声音，或“咔嗒声”/“爆裂声”。这通常是由于性能问题造成的。特别是，如果您还遇到日志中音频缓冲区不足的报告，那么肯定存在性能问题。在波形中看到意外的静默块可能是缓冲区欠载的另一个迹象，尽管这也可能是由于通道映射不正确或信号处理代码中的帧计数不准确等问题造成的。音频通常需要非常快速地渲染，每秒大约 40,000 到 48,000 个样本。速度对于确保可捕获可听范围内的所有频率是必要的 - 采样的音频只能代表低于采样率一半的频率，因此低于 40 kHz 的采样率将具有比 20 kHz （人类可以感知的频率上限）更小的最大可能频率。在虚幻环境中，音频渲染速度不够快会导致称为缓冲区欠载的问题。与大多数音频引擎一样，Unreal 在系统设置中指定大小的缓冲区中渲染音频。这意味着，在音频引擎速度较慢的情况下，音频 API 可能会在音频引擎计算出足够的数据之前请求新的缓冲区。实际上，这意味着虽然各个音频块以正确的采样率呈现，但它们之间可能存在 0 电压间隙，从而导致听觉错误。因此，一些在其他领域合理的代码技术（如果不鼓励的话）如果引入到音频渲染代码中（如果它干扰了音频渲染的速度），则可能会导致问题。根据音频渲染的程度或程序整体表现不佳的程度，听觉故障可以以不同的方式表现出来。不频繁且短暂的缓冲区欠载通常被描述为“爆音”，并且可以在波形中看到为急剧的、意外的跳至零电压。更持续的欠载通常会导致声音被描述为“失真”或“嗡嗡声”，更严重的情况只有短暂的可听声音，或者几乎无法识别其原始资产。然而，您不太可能听到音调和速度的降低，人们有时将其与音频播放速度太慢联系起来 - 这是因为虚幻以正确的速率渲染每个单独的缓冲区，但缓冲区之间存在间隙。有很多事情可能会导致音频代码欠载，但以下是一般准则： - 引擎中任何地方的欠载通常也会影响音频引擎，因此值得通过 Insights 等工具密切关注项目的总体性能。 - 尽可能使用 SIMD 优化，而不是逐个样本地执行操作。 - 注意你所在的线程。音频渲染线程的运行速度比音频线程或游戏线程快得多，因此信号处理和渲染代码通常最好在那里执行。 - 避免在音频渲染线程上进行阻塞调用。这包括 I/O、内存分配、依赖于时间不可预测的代码的互斥体或可能在内部阻塞的第三方调用。
