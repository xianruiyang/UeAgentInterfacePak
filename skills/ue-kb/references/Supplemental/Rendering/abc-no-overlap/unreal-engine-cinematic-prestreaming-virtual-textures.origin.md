### 虚拟纹理概述

MRQ 中预流的目标是减少虚拟纹理 mipmap 的弹出（通常被视为较大纹理中的小图块）。

虚拟纹理系统在绘制场景的基于 GPU 的反馈循环上工作，然后允许系统确定纹理的理想 mipmap 级别。

该信息被反馈到 CPU，CPU 从磁盘加载数据，然后将理想信息上传到 GPU 以在后续帧中使用。

此过程可能需要多个帧才能完全解析每个纹理。

在正常的游戏环境下，反馈缓冲区不会查看每一帧中的每个像素 - 默认情况下，它仅查看每 16x16 像素中的一个 (r.VT.FeedbackFactor)。

使用多个虚拟纹理的材质使情况变得更加复杂，一次只有一个纹理可以为该像素的反馈机制做出贡献，因此在正常情况下，采样 3 个虚拟纹理的材质可能需要 16*3=48 帧才能被考虑，此时在请求发送到 CPU、从磁盘加载数据然后上传到 GPU 之前可能需要额外的帧数。

（旁注：默认情况下使用 MRQ 渲染时，它会将反馈因子覆盖为 1x，这意味着纹理可以更快地自行解析，但它无法克服每像素一个纹理的限制，因此使用多个虚拟纹理的材质可能仍需要多个帧来完全确定它们需要哪些页面，并且一旦发出请求，在从磁盘获取数据、解码并上传到 GPU 时仍然存在多帧延迟）。

该系统的另一个复杂之处是虚拟纹理内存池，它允许开发人员设置他们希望虚拟纹理占用内存的最大大小。

通过使用池，开发人员不必过多担心场景复杂性，因为系统会自动管理池中的 mipmap，并且无论纹理数量有多少，它都会限制纹理可以使用的 VRAM 量。

随着可见纹理数量的增加，池保持相同的大小，而可用的 mipmap 会减少，尊重内存限制，同时平衡艺术内容的需求。

虽然池化系统是有益的，但仍需要考虑一些技术因素。

有多种池类型，您可能需要为不同的纹理格式（例如 DXT1、DXT5 或 BC5 压缩纹理）配置池。

电影渲染队列中经常出现的情况（由于高分辨率输出）被称为“超额订阅”，这是当所有所需 mipmap 所需的内存量大于池的总体大小时的结果。

作为开发人员，您可以通过将更多 VRAM 专用于池（通过增加其大小）来解决此问题。

当池大小尚未增加到足够大时，系统开始降低视觉质量以遵守最大池限制。

当池满时，池中最近最少使用的数据将被踢出池，为新数据腾出空间。

这可能会导致您最近看到的纹理需要再次加载（例如在视频游戏中退出房间并重新进入房间）。

为了避免闪烁和快速卸载/重新加载，在 mipmap 从池中弹出之前，系统支持最小帧阈值（r.VT.PageFreeThreshold，默认为 60 帧）。

这会产生一种可能出现的边缘情况 - 如果您最近看到的 mipmap 太多（即：在最后 60 帧内）并且池已满，则系统无法将它们从池中弹出（由于 60 帧阈值），并且它无法溢出池大小（以继续遵守内存限制）。

在这种情况下，系统将采取两种可能的行为： - 如果为内存池启用了“启用驻留 Mip 贴图偏差”，则该池将减少池中各种纹理的更高质量的 mip 贴图，以便为新请求的数据腾出空间。

这会降低整体质量，但它允许以接近所需水平的 mipmap 引入新纹理，从而保持良好的平均质量。

如果为内存池启用了“Enable Residency Mip Map Bias”，则该池将减少池中各种纹理的更高质量的 mipmap，以便为新请求的数据腾出空间。

这会降低整体质量，但它允许以接近所需水平的 mipmap 引入新纹理，从而保持良好的平均质量。

- 如果未启用，则池别无选择，只能从池中随机弹出 mipmap。

渲染时，系统将选择仍在纹理池中的最高可用 mipmap，即使它不是所需的纹理。

最坏的情况是使用最低分辨率的 mipmap（它始终保存在内存中以便渲染可以继续进行）。

如果未启用，则池别无选择，只能从池中随机弹出 mipmap。

渲染时，系统将选择仍在纹理池中的最高可用 mipmap，即使它不是所需的纹理。

最坏的情况是使用最低分辨率的 mipmap（它始终保存在内存中以便渲染可以继续进行）。

当材质使用多个虚拟纹理时，它们没有同步机制，因此您最终可能会得到更高质量的基色，但会得到质量较低的法线贴图，反之亦然。

默认池默认启用“启用驻留 Mip 映射偏差”，但默认情况下在用户创建的特定池定义上未启用该功能。

### 影片渲染队列预流

在理想情况下，池有足够的空间来容纳所请求的 mipmap，并且不需要降低质量。然而，这仍然给渲染高质量的电影输出留下了一个问题，因为反馈因素（它通知系统它需要哪个 mipmap）仍然会引入延迟，这在最终渲染的帧中是不受欢迎的。为了帮助实现此解决方案，电影预流插件允许您记录所需的 mipmap 数据，然后在实际需要时提前通知流系统。如果池中有足够的空间，则可以在所需的帧上使用这种高质量的 mipmap 数据，并且系统将选择该 mipmap 而不会造成质量损失。由于所需的 mipmap 取决于屏幕分辨率和内容，因此这些预流媒体资源可能需要针对多种分辨率进行预录制，并在每次更新镜头时进行更新（例如相机更改或从场景中添加/删除内容）。

### 设置

实现电影预流的第一步是验证您正在查看的问题确实是虚拟纹理。

您可以在视口中检查这一点，方法是转到“Lit > Optimization Viewmodes > Virtual Texture Pending Mips”，然后在场景中四处飞行相机。

黄色补丁表示所需的 mipmap 尚未加载（如果池没有超额订阅，则将在几帧内加载）。

您可以使用命令“r.VT.FlushAndEvictFileCache”转储文件和 GPU 缓存，这会导致所有场景的虚拟纹理变红，然后重新加载。

如果您的场景没有任何虚拟纹理，您将看到照明模式的较暗版本。

一旦您确认有问题的区域确实是虚拟纹理并且池没有超额订阅（请参阅有关“r.VT.Residency.Notify 1”的早期文档），您就可以继续记录预流资产并配置 Sequencer 来使用它。

由于纹理所需的 mipmap 取决于您的屏幕分辨率，因此您可能需要为不同的分辨率记录不同的预流资源。

由于 Cinematic Prestreaming 插件的实验性质，目前还没有根据分辨率自动选择正确的预流资源的解决方案，您可能需要编辑游戏中的关卡序列以选择正确的资源，或者扩展 Cinematic Prestreaming 系统以支持根据分辨率进行录制和播放。

另请参阅“r.VT.PlaybackMipBias”的实现 现在，您可以尝试以相同的分辨率进行录制和播放，看看这是否有助于解决当前的问题。

场景完成后，您需要使用电影渲染队列插件来生成电影预流资源。

这里有一些文档。

您需要将“Prestreaming Recorder”设置添加到影片渲染队列配置中，并且您还可以考虑 VT Pending Mips（调试）设置。

这将禁用最先进的后处理效果，因为它们不会影响虚拟纹理流，并且会提高渲染速度。

在渲染之前设置“r.vt.FeedbackFactor 1”（MRQ 应该自动执行此操作，但在捕获预流数据时，在渲染之前手动执行此操作可以获得更好的结果。）此外，添加“抗锯齿”设置并将“引擎预热计数：10”和“渲染预热帧”设置为 true。
