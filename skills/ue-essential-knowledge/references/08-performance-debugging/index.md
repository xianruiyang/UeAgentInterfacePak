# 性能、调试与验证

## 覆盖范围

- UE 日志、Message Log、编译日志、Crash Report。
- CPU/GPU profiling、stat 命令、渲染调试视图。
- 自动化 smoke、读回验证、截图验证、dirty resource 检查。
- 异常失败、假成功、异步编译、编辑器缓存和崩溃排查。

## 阅读时机

- 需要分析 UE 的原生错误、运行行为或性能瓶颈。
- 出现崩溃、卡死、编译失败、性能异常、截图不可信或 runtime probe 不稳定。
- 需要设计可重复验收流程。

## 跨区长帧与对象生命周期

资源体积与读取吞吐不能单独解释流送卡顿。数据读取、CPU 初始化和对象销毁可能在不同时间形成峰值；数据已读入也不代表对象及其依赖已经可用。结合实际跨区行为与性能事件定位长帧，再判断应调整内容量、加载时机还是生命周期处理，不能把任何跨区停顿都归于磁盘。

把初始化分散到多帧是在重新分配单帧工作，不等于总工作量按峰值比例减少。若改变原本成组就绪的对象顺序，脚本引用、被依赖对象与支撑几何的可用关系也随之改变；固定每帧对象数不能代替依赖与就绪语义。载入峰值下降仍可能留下离开区域时的集中销毁，比较时需区分相应阶段峰值和就绪时刻，平均帧率不能代替这些判断。历史项目的毫秒预算、批量和分帧实现只说明当时的取舍，不是当前 UE 的参数配方。
