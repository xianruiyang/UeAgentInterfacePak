# 动画与 Control Rig

## 覆盖范围

- Skeleton、Skeletal Mesh、Animation Sequence、Montage、Blend Space。
- Control Rig、RigVM、FK/IK、Full Body IK、Retargeter。
- Sequencer 动画轨道、Control Rig key、骨骼空间与控制空间。

## 阅读时机

- 需要制作或修改动画资产、Control Rig、IK/Retarget 资产。
- 需要排查姿态不动、骨骼偏移、空间错用、关键帧无效或 Sequencer 读回不一致。
- 任务涉及骨骼、控制器、目标点、局部/组件/世界空间转换。

## 从素材到实际角色

沿实际 Skeletal Mesh、Skeleton、Anim Class、姿态图与 Slot/状态分支判断动作由谁消费。资产名字、同骨架或单体预览并不能说明它适合当前持械、比例、接地和行为；落下接滚、击倒接起身等复合素材，可能只应使用其中一段。裁剪、重定向或用 Control Rig/IK 与 Sequencer制作后，仍需接回角色真正使用的姿态与玩法入口，独立 Sequence 不是动作交付的终点。

Montage 的片段边界、播放倍率、Section 跳转和混合共同决定实际节奏。播放返回值还受函数及其返回类型影响，不能把源动画长度直接当作运行时动作、免伤或恢复时长。依赖播放的状态应处理播放拒绝、正常结束与中断，不能只启动时钟而没有退出关系。

## 位移、朝向与加算

先确定角色位移由根运动、移动组件还是受控移动承担，退出同责的旧位移。根轨有平移或素材预览中人物在移动，不证明当前 AnimInstance、姿态分支、Montage 权重和 CharacterMovement 已提取并消费它；移动模式、Mesh 到 Actor 的轴向关系与实际碰撞也参与结果。原地化动作应处理真正承担平移的 Root/Hips 关系，不用拉远相机或无碰撞瞬移掩盖滑移。

加算姿态需要与其类型相符的基姿。自身某帧、另一动画某帧与参考姿态是不同选择，按当前版本的实际语义与属性归一化判断；空的外部引用不必然错误，原始骨轨 Scale=1 也不能证明加算结果的缩放增量为0。普通绝对姿态误当加算可能沿骨链放大，单独播放正常不能排除合成错误。

转向和上下身分层以操作意图、实际身体朝向和命中方向相容为前提。上身先响应、骨盆或下肢跟进是可选表现，不能让武器朝向、Actor Forward 与缓存攻击向量互相矛盾；无输入时不凭零向量重置方向。先找输入门、动作状态、根运动和姿态切换的断点，再决定分层、IK或混合方式，单纯加大插值或延长Blend未必解决截断、重复重启或脚滑。

## 预览与运行证据

连续预览用于判断起势、衔接、接地、收势和终姿，静帧只说明该时刻。单体 Sequence、Montage、实际 AnimBP 合成与游戏内 Character 是不同消费层；源轨数据能解释动作，不能代替后层的位移、命中或控制结果。按当前问题取得相应证据，未运行的部分保持未证，不因编译或保存成功宣称手感成立，也不据此强制新增试玩轮次。动作中断与伤害状态见[游戏框架与状态](../10-gameplay-framework/index.md)。
