## 摘要

虚幻引擎的 FBIK 解算器允许技术动画师按程序调整运行时骨架姿势，以对动态游戏输入做出反应。本教程提供了有关如何正确配置解算器以实现所需姿势的一些见解。这适用于希望在 Control Rig 或 IK Rig/Retargeter 中充分利用 Unreal 的 FBIK 解算器的技术动画师。

### 不只是为了“全身”

初学者经常沉迷于 FBIK 解算器的“全身”性质，并尝试在单个 FBIK 节点中完成所有操作。

这通常会导致效应器竞争、收敛性差或难以调整行为。 FBIK 解算器可以在没有平移根骨骼的单链上很好地工作。它不一定总是应用于“全身”，尽管它也可以做到这一点。 FBIK 解算器仅解算效应器和解算器根骨骼之间的骨骼。

例如，您可以使用 FBIK 解算器驱动单链机器人手臂或龙尾。

### 根设置

了解根设置如何影响 IK 解算至关重要。这应该是设置解算器根和效应器后调整的第一件事。

### 预拉

默认情况下，当效应器平移时，解算器将在应用任何约束迭代之前调整根骨骼的位置。只需将整个骨架移近效应器即可极大地提高收敛速度。

此行为称为“***预”***拉动，因为它在***解决约束之前拉动骨架。

预拉还可以***旋转***整个骨架。这可能非常强大，因为你可以让你的角色将整个身体朝着翻译效应器的方向倾斜。可以使用预拉设置独立控制每个轴的旋转量。

您可以根据需要完全或按轴混合预拉平移和旋转。提示：调整预拉行为时将迭代设置为 0，以查看它对骨架的确切影响。

### 引脚至输入

如果您不想翻译解决方案的根，只需将其设置为“固定到输入”即可。它将强制解算器表现得像普通的单链 IK 解算器，并且只允许在解算器根骨骼上旋转。

### 自由的

在此模式下，解算器根仅在需要时才会平移以帮助效应器到达其目标位置。这使骨骼更像是一个物理刚体，但有时看起来不自然，因为生物通常会移动整个身体，而不是完全伸展四肢，这会使它们失去平衡。

### 骨骼设置

在 FBIK 中，“根”骨骼是解决方案的基础。

位于从效应器到解算器根的直接谱系的层次结构中的所有骨骼都包含在约束求解中。不属于该直系谱系的兄弟姐妹和子代会被简单地更新，就好像它们是静态父代一样，但不包含在核心约束求解中。

为这些骨骼创建骨骼设置**不会产生任何效果**。

### 排除的骨头

如果效应器和解算器根之间的直线上有一根骨骼，而您***不想***受到解算的影响，则可以排除该骨骼。排除的骨骼被视为其父骨骼的刚性延伸，并且根本不会旋转。当骨架具有内联扭曲骨骼或仅具有语义含义但不应该摆出姿势的额外“组织”骨骼时，这有时很有用。

### 首选角度

当效应器“挤压”肢体（靠近骨骼中最近的分支）时，对骨骼应用首选角度会直接旋转骨骼。

您可以通过将解算器迭代设置为 0 并移动效应器来压缩肢体来查看首选角度的确切效果。当效应器挤压肢体时，您将看到骨骼根据这些角度旋转。

通过以首选角度旋转骨骼，您可以控制在 IK 压缩肢体时骨骼弯曲的方向。例如，这可用于确保肘部和膝盖沿着正确的铰链以正确的方向弯曲。 *在*解决任何约束之前应用首选角度，以便在约束接管之前，肢体以弯曲配置开始，在所需的方向上。

### 旋转/轴限制

优选的角度简单、快速且稳健，并且应该优先于旋转限制。但有时您需要防止骨骼旋转超过一定程度。在约束迭代期间应用旋转限制，其中骨骼在每次迭代时被强制旋转回到允许的范围内。

限制的一种特殊情况是设置一个关节的两个轴都被锁​​定。在内部，这将约束行为更改为铰链约束的行为。这些通常更坚固，对于机器人或膝盖和肘部等铰链关节特别有用。

通常，最好谨慎使用锁定或有限的关节角度，并且仅当“首选角度”和“刚度”无法达到所需效果时才使用。有可能创建一个如此锁定或受限的配置，需要多次迭代才能收敛，并且如果约束相互冲突，可能会产生“摆动”。

### 旋转刚度

这是平衡 IK 对骨骼中不同关节的影响的有用且稳健的方法。如果您希望骨骼根本不旋转，可以将旋转刚度设置为 1.0。

这比使用锁定/有限轴更加稳健。增加骨骼的旋转刚度将导致其他骨骼通过更多旋转来进行补偿以实现收敛。

### 拉链阿尔法

效应器的这一功能可用于在约束求解之前旋转由效应器控制的整个肢体以指向效应器。如果将解算器迭代设置为 0，则在移动效应器时您可以看到拉链 Alpha 的效果。

拉链 Alpha 和首选角度可以帮助在解决约束之前将骨架拉成所需的形状。默认情况下，拉链 Alpha 处于开启状态 (1.0)。尽管通常需要将其关闭，因为在您不希望使用更广泛的骨骼来实现目标的情况下，它可能会使四肢过度活跃。

### 子链（5.4 中的新增功能！）

虚幻引擎 5.4 中的新增功能称为“子链”，它允许您在全身 IK 中定义骨骼链，并在预通道中单独求解。这使您能够指示解算器让主体不受影响，直到子链达到其完全延伸。

### 为什么我们需要这个？

此功能解决了一个常见问题，即用户更喜欢 IK 解算器保持身体不变，除非或直到肢体无法到达更远的地方。例如，如果角色伸手去够触手可及的门把手，您现在可以完全防止手臂影响身体。

默认情况下，手部执行器会将微小的变化通过手臂传播到脊柱。发生这种情况是因为所有关节约束都组合在一起，并且有平等的机会为最终姿势做出贡献，即使某些骨骼并不严格要求实现收敛。由于收敛很少在单次迭代中实现，因此每当效应器移动时，整个身体通常都会移动，无论移动多么轻微。

如果效应器目标位置不规则移动（例如，基于高度起伏地形上的地面对准光线投射），则此问题尤其成问题。这些快速的变化可以在整个身体中传播，导致可怕的“全身晃动”。

这种情况很难避免。您唯一的选择是通过增加刚度来稳定身体（这需要更多迭代才能收敛），或者在 FBIK 解算器之前在手臂和腿上应用两骨 IK。对目标位置进行严格过滤可能会有所帮助，但理想情况下，您希望指示解算器本身不干涉主体，除非它绝对需要移动主体以实现收敛。

### 如何使用子求解

幸运的是，5.4+ 中的解决方案非常简单：

每个效应器现在都包含一个称为“链深度”的参数。默认为0，表示该效应器不会创建任何子链。大于零的值定义了要包含在该子链中的层次结构上的骨骼数量。例如，对于手腕处的 IK，链深度为 3 将创建一条从手腕到锁骨的子链。您可以通过设置效应器的链深度将任意数量的效应器转变为子链。

为了使子链发挥作用，您需要设置求解器的“子链迭代”。默认值 0 表示此功能默认关闭。将其增加到 5-10 之间的值通常足以让子链完全收敛到可达到的目标。将主迭代设置为 0 会很有帮助，这样您可以在调整链深度和子链迭代时隔离子求解的影响。

在内部，约束基于链进行分桶并独立求解。因此，您通常可以减少主迭代的数量，因为它们要做的工作较少。
