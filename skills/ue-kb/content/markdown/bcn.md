GPU 性能瓶颈主要是纹理采样操作（GPU 内存带宽使用越多 - GPU 绘制图形越慢）。

GPU 需要经常传输纹理，因此更小的纹理尺寸 => GPU 需要更少的带宽来将纹理获取到着色器核心 => GPU 绘制图形的速度更快 [1]。

BCN 纹理压缩算法。

RGB565表示红色通道为5位，绿色为6位，蓝色为5位。

R10G10B10A12表示红色通道为10位，绿色为10位，蓝色为10位，Alpha为12位。

BCn 压缩的想法是，在任何小区域（例如 4x4 图块）内的许多图像中，颜色几乎没有变化 => BCn 使用它来减少 GPU 纹理采样负载。

图像被分成 4x4 像素图块。

每个图块被压缩为 8 或 16 字节块（取决于使用的 BCn）。

每个图块通常是两种对比色之间的渐变或混合。

基本压缩块（例如 BC1）包含 RGB565 格式的 2 个端点（对比色）和 16 个 2 位索引（每个像素一个 2 位索引）。

因此，块的调色板为 2^(index_bitlen)= 2^2= 4 种颜色：2 个端点 + 端点之间混合的 2 种颜色。

像素索引值告诉它的颜色：index = 00 表示像素具有端点 0 颜色 (c0)，index = 01 表示像素具有插值颜色 c1 = 2/3 * c0 + 1/3 * c3，index = 10 表示像素具有插值颜色 c2 = 1/3 * c0 + 2/3 * c3，index = 11 表示像素具有端点 1 颜色 (c3)。

* 压缩器分析图块并找到图块的对比颜色（端点）。

在这里，它们似乎位于像素 0 和像素 15，但在不同的图块中，它们可以在不同的像素处找到。

### BC1

数据：RGB565（+ 可选的 1 位 Alpha）。压缩率：64 位/块 = 0.5 字节/像素。块：2x RGB565 端点（2x 16 = 32 位）+ 16x 2 位索引（16x 2 = 32 位）。优点/缺点：[+] 最佳压缩率 (1:8) => 小 => 快速，[+] 用于基色、剪切材质基色 + 二进制 alpha（树叶、格栅、栅栏等...），[+] 用于法线，如果 VRAM 非常紧张，则打包数据贴图，[-] 不利于平滑渐变（RGB565：绿色有更多位，因此平滑渐变有绿色/紫色条带），[-] 不用于平滑渐变或微妙的颜色变化：天空、皮肤等...BC1 如何存储可选的 1 位 Alpha？每个块可以通过两种方式进行压缩，并获得相同的结果（简并性）：如果交换压缩块的端点和反向索引，则会得到相同的结果。 BC1 打破了这一点，隐式存储 1 个额外位。两个 16 位端点（c0 和 c3）被解释为两个 16 位整数，因此：如果 c0 > c3：块使用 4 种颜色 = 2 个端点 + 2 个插值，如果 c0 < c3：块使用 4 种颜色 = 2 个端点 + 1 个插值 + 1 个透明黑色。 * 在“BC1 Alpha 模式”中，索引 = 11 表示像素是透明的（Alpha 为零的黑色）。这使得它非常适合剪切材料：格栅、栅栏、植被等......但是，双线性纹理过滤引入了黑色边缘。

解决方案：1）将 Alpha 阈值设置得较高或 2）在着色器中将插值颜色除以插值 Alpha 以消除变暗，或 3）在渲染纹理时使用“over”运算符（还需要按从后到前的顺序对透明像素进行排序）[1，注释部分]。

### BC4

数据：Grayscale8 - 一个通道。压缩率：64 位/块 = 0.5 字节/像素。块（64 位）：2x 8 位端点（2 字节）+ 16x 3 位索引（48 位 = 6 字节）。优点/缺点： [+] 最佳压缩率 (1:8) => 小 => 快速，[+] 打破简并以获得更好的结果，黑白之间的锐边，[+] 用于黑白纹理或未压缩的灰度（高度图，掩模等...），[- ] 一个通道意味着 BC4 无法压缩压缩纹理也打破简并：如果 c0 > c3：块使用 8 种颜色 = 2 个端点 + 6 个插值，如果c0 < c3：块使用 8 种颜色 = 2 个端点 + 4 个插值 + 黑色 + 白色。具有未签名和签名变体。无符号：对 0 和 1 之间的值使用常规 8 位 UNorm 编码，有符号：对 -1 和 +1 之间的值使用 8 位 SNorm。特殊索引对应于-1 和+1。 * BC2、BC3、BC5 - 是 BC1 和 BC4 的组合。

### BC3
