这正对应正文里“把当前屏幕宽高中的一个像素比例取出来，再在左右上下方向各偏移一个像素”的做法。具体到这一帧，作者先实现了水平方向的单步偏移：以原始 `TexCoord` 为基准，加上 `InvSize * (1, 0)`，得到右侧或左侧相邻一个像素的采样坐标，再把这个坐标送回 `SceneDepth` 采样。后续只要把方向向量改成 `(-1,0)`、`(0,1)`、`(0,-1)`，就能得到四个方向的深度邻域，为后面的边缘差值计算做准备。

- 两路深度各自经过一个 `Mask (RGB)` 节点后送入 `Subtract`；
- `Subtract` 的输出继续向右传递到后续更长的处理链。

左侧材质预览球已经能看到明显的黑白分界和几层灰色过渡带，说明当前网络确实在比较相邻像素之间的深度变化，而不是单纯显示原始深度。结合正文“把原始颜色和深度值与偏移值进行比较做减法，如果差值不大显示黑色，差值越大显示白色”来看，这一帧对应的就是边缘提取的核心原理：当当前像素与邻域像素深度接近时，减法结果接近零；当深度跳变明显时，减法结果增大，于是边缘位置被提亮出来。
这张图继续把边缘检测从“单方向比较”扩展成“多方向汇总”。画面中可以可靠辨认出三组相似的局部结构：每组都是左侧一个 `Add` 生成偏移 UV，随后进入 `SceneTexture:SceneDepth`，再经 `Mask (RGB)` 后送入一个 `Subtract`。这些 `Subtract` 的结果继续向右汇聚，其中中上部还能看到一个 `Add` 节点在合并两路结果，右侧另一个 `Add` 节点的 `B` 参数明确为 `1.0`，说明当前网络已经从单一差值进入组合与结果整形阶段。

左侧预览球仍保持黑白边缘带的测试状态，说明这些多路分支都服务于同一个边缘提取目标。结合正文“从右左上下四个方向各偏移一个像素距离，然后与原始场景深度比较做减法”可知，这一帧对应的是把多个方向的深度差统一收集起来：先分别计算相邻像素在不同方向上的深度跳变，再通过后续 `Add` 等节点把这些跳变量合并，得到更稳定、更完整的轮廓强度。这样做的目的，是避免只看单一方向时漏掉部分边缘，让扫描线后处理在复杂场景里仍能把物体轮廓较完整地勾出来。
