# 通用白盒方法论（LevelDesign skill）

> 说明：本文件是**通用**的白盒/Blockout 方法论参考。  
> 在当前项目中，请始终优先遵守项目内 `docs/levelDesignDocs/` 的硬规则；当项目内规则缺失或需要补充方法论时，再使用本文件。

## 1. 工作流（建议顺序）

### 1.1 定义验证目标

先锁定本关卡要验证什么：

- 核心体验
- 核心玩家动词（重复动作链）
- 起点与终点状态
- 成功判定/验收标准
- 明确不做的范围
- 关键路径（critical path）
- 预期的高潮点与恢复点（高低起伏）

如果这些不清晰，白盒会漂移为“堆体块/做装饰”，而不是“验证玩法与结构”。

### 1.2 锁定度量（Metrics）

在细化布局之前先固定基本度量（否则无法下“可达/可读/节奏”结论）：

- 角色胶囊体/占用尺寸
- 相机高度与 FOV
- 移动速度、跳跃距离（水平/垂直）
- 门宽、走廊宽、楼梯宽
- 掩体高度与间距
- 常见战斗/交互距离

度量不稳定时，不要评价布局“好/坏”，只能说“候选方案”。

### 1.3 先画结构，再摆几何

先定义拓扑（Topology），再摆几何：

- 关键路径
- 支路
- 回环（loops）
- hub/汇合点
- 地标（landmarks）
- 安全区
- 压力区（战斗/解谜/跑酷压力）

优先“意图清晰的简单结构”，不要做“复杂但不可读的迷宫”。

### 1.4 构建玩家引导（优先空间，其次 UI）

优先用空间引导玩家，而不是依赖 UI 标记：

- 路径/节点/几何指向性优先
- 地标与取景框架其次
- 对比、开口强调、光照再其次
- 敌人/奖励/声音/事件最后补充
- 强 UI 标记是最后手段

使用一个简单规则：先让玩家“预览目标”，再允许玩家“接近目标”，最后才要求“执行（跳/解/战）”。

### 1.5 内容分布（主线只放必须）

关键路径只放“必须内容”：

- 目标推进
- 必要教学
- 核心机制/战斗使用
- 关键过渡（节奏/空间切换）

支路必须提供“可解释的可选价值”：

- 奖励
- 信息
- 战术优势
- 捷径或回流效率

若支路没有任何价值，直接删掉或合并。

### 1.6 节奏塑形（Pacing）

把节奏理解为以下组合：

- 活动类型
- 强度
- 持续时间
- 过渡方式

用稳定的拍点（beat）模式组织：

- 定向（orient）
- 热身（warm up）
- 执行（execute）
- 施压（对玩家形成路线、时间或空间压力）
- 释放（release）
- 恢复（recover）

高低交替；高潮前要有铺垫，高潮后要给恢复空间。

### 1.7 白盒迭代（分三轮）

推荐三轮迭代：

- `V1`：验证体量、路线、开口、竖向变化、预览点
- `V2`：加入玩法点位、遭遇/解谜、奖励、风险、跑酷钩子
- `V3`：调引导、调节奏、调路径可读性、调重复与学习顺序

每一轮只改少量变量，避免“同时改太多导致因果不可追”。

### 1.8 测试并锁骨架

记录可复用的试玩证据：

- 实际路线
- 迷路/困惑点
- 死亡点/失败点
- 停留过久点
- 疲劳/重复点
- 实际节奏时长（beat timing）
- 非预期但有价值的玩法

在灰盒/美术交接前锁定（不要让后续制作随意破坏）：

- 关键路线
- 关键视线
- 关键高差
- 关键掩体
- 关键地标
- 关键节奏节点

## 2. 规则集（便于快速审查）

### 2.1 引导规则

- 让玩家知道：去哪、什么值钱、如何恢复方向感。
- 主路径必须比支路更好读。
- 玩家进入新空间几秒内应能识别目标或地标。
- 关卡在压力下也要读得出来，而不是只在慢速探索下成立。
- 若关卡只能靠强 UI 标记才不迷路，优先修空间而不是加 UI。

### 2.2 内容分布规则

- 把支路当“功能”，不是当“填充房间”。
- 必要教学不要藏在可选路上。
- 用回环恢复方向、提升回流效率、或创造战斗换位空间。
- Hub-and-spoke 结构只有在“每条 spoke 有明确职责、回到 hub 会发生有效变化”时才成立。
- 删掉重复房间、空回溯、无奖励/无信息的分支。

### 2.3 节奏规则

- 开头比你直觉更“安静”一点更好（给学习与定向）。
- 避免连续堆叠太多高压段。
- 新机制按“教 → 练 → 测 → 反转/组合”组织。
- 结尾不一定要“最难”，但必须让人觉得“收束且值得”。
- 段落拖沓时，先改活动组合或结构，不要只加敌人/机关硬拉长度。

### 2.4 审查顺序

审查现有白盒时，按以下顺序检查：

1. 度量（metrics）
2. 关键路径（critical path）
3. 地标与视线（landmarks/sightlines）
4. 引导清晰度（guidance clarity）
5. 支路功能（side path function）
6. 节奏与拍点（pacing/beat flow）
7. 灰盒/美术交接风险（handoff risk）

## 3. 产出物（可选）

必要时产出这些中间物（让白盒“可验收/可复盘/可交接”）：

- 关卡设计卡（level design card）
- 度量表（metrics table）
- 拓扑草图（topology sketch）
- 节奏拍点表（beat sheet）
- 强度曲线（intensity graph）
- 白盒迭代记录
- 试玩日志（playtest log）
- 骨架锁定交接说明（locked skeleton handoff note）

## 4. 常见失败模式

- 白盒看起来很“宏大”，但没有验证核心动词。
- 玩家能走，但读不出方向/价值/危险。
- 支路体量远大于它提供的功能价值。
- 战斗/解谜/探索段过长，节奏被拉平。
- 教学藏在可选内容里，导致主线玩家不会用机制。
- 美术交接改动了关键开口/路线/掩体/地标，直接把关卡结构做坏。
