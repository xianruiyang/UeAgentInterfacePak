# 跨楼层连接与设施规则

## 1. 目的

本文档专门约束跨楼层连接单元，以及门、楼梯、斜坡、电梯、`Zipline` 等设施如何附着到空间与边界。

如果你是在按流程做白盒，请先看：
- [总体白盒搭建流程.md](总体白盒搭建流程.md)

## 2. 先有跨楼层连接单元，后有设施

不要先问“这里放电梯还是 `Zipline`”。应先问：
- 它连接哪两个可站立空间
- 角色从哪接近
- 角色到达后从哪离开
- 这条连接属于主路径、支路、捷径还是回环

设施只是这条连接单元的实现形式。

## 3. 白盒阶段的默认模板

### 3.1 下层平台外挑型

下层平台相对上层平台多出一部分，在外挑部分布置楼梯、斜坡、电梯、`Zipline` 等设施。

### 3.2 上层开洞型

上层开一个角色可通过的洞，下层保持完整完成面，再将竖向设施贴着洞边或洞侧布置。

### 3.3 不只允许相邻层连接

跨层连接不应被限制为：
- `1L -> 2L`
- `2L -> 3L`

也允许：
- `1L -> 3L`
- `3L -> 1L`
- `2L -> 中间平台 -> 4L`

## 4. 每条跨楼层连接必须先锁的字段

### 4.1 最小字段

至少先定义：
- `upper_use_zone`
- `lower_use_zone`
- `approach_side`
- `exit_side`
- `landing_surface_upper`
- `landing_surface_lower`
- `required_clearance`

### 4.2 可执行契约字段

中型以上白盒还必须补齐：
- `upper_walkable_area`
- `lower_walkable_area`
- `approach_corridor`
- `exit_corridor`
- `required_opening`
- `forbidden_blocking_volume`
- `support_pattern`
- `must_pass_width`
- `must_pass_height`

这些字段的作用是把“这条连接大概怎么走”变成可生成、可验收的结构约束。

## 5. 正确生成顺序

默认顺序固定为：
1. 定义上层可站立区和下层可站立区
2. 定义上端接近通道和下端离开通道
3. 定义所需洞口、平台边或外挑边
4. 定义支撑模式
5. 定义禁止阻挡体积
6. 最后再放设施主体

禁止顺序：
- 先摆设施，再补上下通行空间
- 先铺整层 floor，再挖洞/塞楼梯/塞电梯

## 6. 设施默认贴合规则

### 6.1 门

- 门必须从门户区间派生位置
- 朝向由通行方向决定
- 门框与墙之间不应出现无法解释的缝
- 门应同时匹配墙厚：门可视体厚度应 ≥ 周边墙厚；必要时可做 1~2cm overlap 消除“像素裂缝线/漏光”观感
- 门洞/通道口优先用 `level_spawn_wall_with_opening` 生成（或等价的“自动拆段墙”方式），避免手工拆墙导致：
  - 视觉上像连通但实际被薄墙段封死
  - 墙段对齐误差积累形成大缝/漏光
  - 门洞净宽/净高与门不一致
- 门洞生成后，白盒阶段至少做一次硬验收：
  - `level_sweep_capsule` 或 `level_sweep_capsule_path`：验证门洞净空与通行宽度
  - 必要时补一张 `screenshot_viewport_buffer(SceneDepth/WorldNormal)`：快速暴露“门墙穿插/漏缝/挡死”等空间错误

### 6.2 楼梯与斜坡

- 必须从上、下 `landing_surface`（落脚面）与路径方向派生
- 必须先存在真实上层可站立区和下层可站立区
- 不得只摆一个构件，再补周围 floor

### 6.3 电梯

- 先定停靠层与两侧 `landing_surface`（含接近/离开位与净空）
- 再定平台 footprint（平台尺寸必须服务 `landing_surface`）
- 再由平台反推 `support_opening_footprint`（井口/洞口）与禁止阻挡体积，保证运动净空与到站可离开
- 最后再放电梯 actor 与触发/交互体积

默认要求：
- 电梯平台必须落在真实完成面上
- 平台停靠后应与周围 floor 连续，不应靠玩家跳上去
- `support_opening_footprint`（井口/洞口）必须覆盖平台运动路径，并与平台 footprint 匹配到“无可掉落缝、无到站阻挡”的程度：洞口过大容易出现掉落缝/不贴合观感，洞口过小会导致到站被挡死/穿插
- 电梯不默认围井墙
- 只有 shaft 承担额外职责时，才保留井墙
- 不得先把电梯关进井里，再勉强留一条窄缝给玩家

### 6.4 Zipline

白盒阶段默认把 `Zipline` 当成“跨层连接设施”的一种实现：交互本质可以简化为传送，但结构与视觉语义必须像一条把上下端连接起来的绳索/滑索。

在当前项目里，常见用法是竖向或斜向的上下转换；是否做水平连接由设计包的连接单元决定。

推荐的结构语义模板（优先）：
1. 洞边附着型
   - 上层有角色可通过的洞
   - `Zipline` 贴在洞边
   - 玩家从洞边内侧接近交互
   - 端点落脚平台应是“从洞边向洞内外挑”的 balcony/pier（伸入洞内），不要把端点落在 ring 完成面上再额外铺一块薄板，容易重复几何打架且语义像临时摆件
2. 平台边附着型
   - `Zipline` 贴在高处平台边
   - 下端接真实下层平台或完成面

若使用其他方向的连接，也必须满足：两端落在可行走完成面上、接近/离开位成立、周边无顶死/对空/被围死等语义失败。

自动化验收建议：对 `Zipline` 两端附近各做一次 `level_get_nearby_actor_obbs`（或等价方式）检查，确认附近确实存在对应落脚面 actor，而不是落在空区/漂浮块上。

禁止：
- 悬在洞中央
- 接到虚空
- 接到场景外
- 接到玩家到达后无法离开的地方

## 7. 设施支撑与玩家通道必须分离

不要把“设施支撑口径”当成“玩家通道口径”。

至少要区分：
- `support_opening_footprint`
- `portal_clear_width`
- `approach_zone`
- `landing_surface`

否则很容易出现：
- 设施贴合对了，玩家走不过去
- 玩家通道对了，设施又像悬空或插进地面

## 8. 设施贴合的最低要求

每个设施都必须能回答：
- 它附着在哪条边、哪个洞边或哪个平台边
- 它服务哪两个可站立空间
- 角色从哪一侧接近
- 角色从哪一侧离开

如果回答不了，它就只是“摆上去了”，还没有真正成为关卡结构的一部分。

## 9. 逐条竖向连接验收

每条竖向连接都必须单独通过以下检查：
- 上端可接近
- 下端可接近
- 使用过程没有被阻挡体积封死
- 到达后可离开并继续推进
- 周边不存在不可解释缝隙、悬空落点或伪装成路的假 floor

不能只看整体截图，也不能只看 actor 存不存在。

## 10. 什么时候必须返工

出现下列情况之一，应回退到跨楼层连接单元重做：
- 电梯、`Zipline`、楼梯被墙围死
- 设施必须靠硬调 `transform` 才勉强能用
- 设施看起来在连层，实际上接近位或离开位不成立
- 设施与周边 floor/wall 有无法解释的缝
- 为了修贴合把设施类型改坏了
- 只有设施 actor，没有对应的连接契约
- 没做逐条竖向连接验收
