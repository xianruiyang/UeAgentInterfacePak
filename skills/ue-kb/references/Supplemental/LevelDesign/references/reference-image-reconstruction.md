# 参考图重建规则与复盘

## 目的

这份文档把两类内容合并到一起：

- 参考图驱动白盒重建时的验收硬规则
- `map.png` 白盒复刻失败后得到的关键复盘

它只在“参考图重建”类任务里使用，不作为一般白盒总则。

---

## 一、硬约束

对白盒复刻类任务，验收时必须满足以下条件：

1. 在同一次请求里同时重新加载参考图和当前截图
2. 不得只依赖聊天上下文里的旧图记忆
3. 不得只加载截图而不加载参考图
4. 不得先看图、隔一轮再凭印象写验收结论

如果上述条件不满足，则本轮验收无效。

### 最低执行方式

至少同时加载三张图：

- 参考图
- 当前主视图截图
- 当前顶视图或辅助结构截图

建议（不减少上述三类输入）：

- 额外加一张 `buffer` 调试图（优先深度或法线），用于更可靠地发现：穿插、悬空、遮挡、缝隙、楼梯被挡等空间错误（例如 `screenshot_viewport_buffer` 的 `SceneDepth/WorldNormal`）。

如果重点在局部，例如楼梯、走廊、平台或房间连接，可再加局部截图，但不能减少上述三类输入。

---

## 二、为什么必须这样做

参考图重建里最常见的误判不是“没看到”，而是：

- 左右整体反了却没发现
- 主楼梯和主走廊关系错了却看成“差不多”
- 通道只是留空，没有真实连接，却被误判为成立
- 房间盒子都在，但空间组织完全不对
- 因为上一轮“看起来比以前好”，就把当前错误结果说成通过

同请求双图验收的作用，就是强制把：

- 当前实际结果
- 参考目标

放在同一判断面里。

---

## 三、参考图任务的最低流程

### 1. 先做中间产物

不要直接从参考图跳到几何体。

至少先补：

- 拓扑草图
- 路线图
- 标高表
- `cutaway` 规则

### 2. 先重建主骨架，再做局部轮廓

优先顺序应是：

1. 主路径
2. 关键连接
3. 关键高差
4. 主要空间身份
5. 最后才是轮廓和局部切面

### 3. 验收必须明确回答的问题

每轮至少要明确回答：

1. 左右映射是否正确
2. 主 spine 是否成立
3. 开放通道是否真的是连接，而不是“墙没封住”
4. 主要空间是否仍只是盒子堆叠
5. 哪些点比上一轮更好，哪些点仍未达标

如果答不上这些问题，就不应该宣布通过。

---

## 四、失败复盘：之前为什么会做坏

之前 `map.png` 白盒复刻失败，根因不是命令不够，而是流程错了。

### 1. 把单张透视图当成了充分几何输入

单张透视图最多支持：

- 识别主空间
- 识别大概层级
- 识别大概路线节点

它不足以直接支持：

- 精确平面拓扑
- 精确切面策略
- 精确楼梯连接
- 精确房间尺度

### 2. 缺少中间产物

真正缺的不是命令，而是：

- 平面拓扑图
- 一层/二层关系表
- 楼梯连接表
- `cutaway` 保留/删除规则
- 主路线节点图

这些没落出来，就不应该进入批量生成。

### 3. 把 Modeling 放错层级

`Modeling` 适合：

- 白盒几何体生成
- 局部修形

它不适合替代：

- 空间拓扑规划
- 路线节点规划
- 剖切策略规划

### 4. 把截图当成结构判断

当时实际做成了：

- 先看体块和楼梯有没有出现在画面里
- 再靠调相机去逼近参考图

这会导致：

- 结构错误被视角掩盖
- 轮廓相似度被高估
- 拓扑错误被低估

---

## 五、以后再做参考图重建时，最低必须补什么

### 1. 拓扑草图

先画出：

- 哪些是房间
- 哪些是庭院
- 哪些是走廊 / 平台 / 阳台
- 哪些区域上下叠置

### 2. 路线图

先标：

- 主入口
- 核心 hub
- 一层到二层的主要连接
- 左右关键空间的串联方式

### 3. 尺寸与标高表

至少需要：

- 一层完成面
- 二层完成面
- 平台高度
- 各主空间的大致宽深高

### 4. `cutaway` 规则

先定：

- 哪一侧是剖切面
- 哪些墙必须保留
- 哪些地板保留完整
- 哪些面只是为了看清结构而删掉

## 结论

参考图白盒任务最容易失败的原因，不是少一个命令，而是：

- 透视图驱动的体块拼接
- 截图印象驱动的验收

以后必须先把：

- 拓扑
- 路线
- 标高
- `cutaway`

这些中间产物做出来，再允许进入几何施工。
