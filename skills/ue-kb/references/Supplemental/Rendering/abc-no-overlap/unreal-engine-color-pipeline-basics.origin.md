### 概览

文章由 Matt O 撰写。在虚幻中处理颜色和颜色空间时，了解这些颜色在渲染管道中移动时会发生什么情况非常重要。我们将概述值何时以及如何从 sRGB 转换为线性、后处理中发生的情况以及到达最终像素时发生的情况。

### 一些颜色术语

色彩空间 - 将为红色、绿色、蓝色和白色生成的特定颜色。可以定义不同的颜色空间，这将导致 1,0,0（例如）在一个颜色空间中比在另一个颜色空间中成为更饱和的颜色。示例包括 Rec709、Rec2020、sRGB、ACES 2065-1 等。 颜色编码 - 如何以数字方式表示值，以及该表示应产生多少光。示例包括 Linear、sRGB、Gamma、PQ (ST 2084) 和各种供应商特定的日志编码。 Gamma - 一种非线性颜色编码，用于对亮度值进行编码。该方程可以表示为 OutValue = A * InputValue ^ Y。其中 A 通常是常数 1.0，Y 值是我们所认为的“伽玛校正”值。色域 - 可以由颜色空间或输出设备表示的颜色子集，或给定时间在图像中找到的颜色集。线性颜色空间 - 具有线性颜色编码的颜色空间。所表示的光量与存储的值成正比。因此，数量加倍就会产生两倍的亮度。 sRGB - 在计算机图形学（以及虚幻引擎）中，sRGB 指特定的颜色空间，也是特定的颜色编码。可以有线性 sRGB，也可以有 sRGB 编码的 sRGB。如果没有明确上下文是关于颜色空间还是颜色编码，则该术语可能会引起混乱。

### 简化的渲染管线

渲染过程通常有四个阶段： - 获取纹理输入并将其带入线性编码颜色空间 获取纹理输入并将其带入线性编码颜色空间 - 确定图元可见性、光线如何与表面交互，将结果放入场景颜色 确定图元可见性、光线如何与表面交互，将结果放入场景颜色 - 然后，对场景颜色中的所有内容进行后处理 然后，对场景颜色中的所有内容进行后处理 - 最后，将其显示到视口设备中 最后，将其显示到视口设备中

### 典型的颜色转换

引擎的隐式工作空间是Linear sRGB。通过从纹理中存在的编码进行转换，将纹理导入到工作空间中。目前，这是由纹理上的 sRGB 复选框处理的，这表明纹理文件已经是线性的（标志关闭），或者文件具有 sRGB 编码（标志打开）。渲染和后处理全部在线性空间中进行，直到我们到达电影色调曲线（色调映射器的一部分）。色调曲线将场景的大动态范围压缩至 0.0-1.0 范围。最后，我们将线性（应用外观）转换回 sRGB 编码像素进行显示。

### 纹理 sRGB 到线性转换

因此，给定一个以 sRGB 编码的 PNG 文件，我们得到了从 0 到 255 的渐变（这里用这条蓝线表示）。当读取这些值时，它们会通过 sRGBToLinear 函数进行转换，从而降低值。这意味着输入值 128（或 0.5）将变为线性值 0.214。这反过来又允许我们表示许多非常暗的值，即使我们的输入文件的位数很少。当数据变成线性时，需要更多的位来表示线性值。我们在场景渲染期间使用 16 位浮点，这使我们能够同时表示非常小的暗值和非常高的亮值。渲染管线，扩展

### RGB 线性渲染

如果您正在查看 RenderDoc 或 GPU Visualizer 之类的各种渲染阶段，我们会在线性空间中完成所有这些工作。

当我们说“RGB 线性渲染”时，我们指的是这里突出显示的所有内容：这就是我们可以进行后处理之前必须发生的所有事情。

这意味着，在我们开始后处理之前，在无光照、不透明、自发光材质中指定的颜色值正是 SceneColor 缓冲区中的值。

后处理是一系列阶段或通道。

在本次讨论中，我们将色调映射器与前面的一组后处理通道分开，其中包括时间抗锯齿、景深、运动模糊等操作。

这些通道对线性像素值进行操作并产生线性像素值。

色调映射器将线性场景转换为可以发送到显示设备的信号。

色调映射器是修改输出像素的一系列步骤。

它们是对相机镜头及其成像传感器中通常发生的操作的模拟。

下面列出的步骤都是色调映射器的一部分。

有时我们想要关闭色调映射器的“外观”。

但是，如果我们使用控制台命令 showflag.tonemapper 0 关闭色调映射器，那么我们剩下的就是输出设备转换步骤，这可能并不理想，特别是因为这也会影响光晕、晕影和颜色校正等内容。

然而，我们可以在体积或相机的后处理设置中控制每个单独功能的贡献或效果。

注意：在 4.26 之前，无法在后处理设置中控制色调曲线。

可以通过将其贡献设置为 0.0 来禁用色调曲线。

通常，想要关闭色调曲线的用户可能还想关闭扩展色域颜色校正。

该操作是通过增加已经有些饱和的颜色的饱和度来与色调曲线协调的。

这使得它们在应用色调曲线后看起来更好。

电影色调曲线具有改变曲线整体效果的参数，但我们没有直接替换色调曲线的参数。

如果您需要完全不同的色调曲线，则应考虑使用 OCIO，如下所述。

### UE 的 HDR 显示

目前，UE 有两个 HDR 显示目标：ACES1000nits 和 ACES2000nits。处理 HDR 显示器的输出发生在“输出设备”步骤中。当这些目标被激活（通过 r.HDR CVars）时，电影色调曲线将关闭，并应用不同的色调曲线以及不同的设备输出编码。

### 休闲色彩管理

在 4.26 中，我们还在引擎中实现了对 OCIO 颜色管理的支持。您可以在我们的文档中阅读有关如何设置和使用它的更多信息。但这如何适应我们迄今为止讨论的颜色管道呢？ OCIO 颜色管理的作用是在各种供应商工具中提供一致的颜色转换。在 UE 情况下，OCIO 接管色调曲线和输出设备的职责。启用后，如下所示，色调曲线和输出设备将自动禁用。需要注意的是，虽然 OCIO 被描绘在 Tonemapper 旁边，但它是独立于 Tonemapper 的。如果您选择通过 Showflag 禁用色调映射器，OCIO 仍会发生，并将接收线性场景颜色。如果您选择使用后处理材质（ReplaceTonemapper），OCIO 将随后发生，您将需要仔细管理 PPM 的结果，因为它将成为 OCIO 的输入。

### OCIO 和后处理材料

当您使用 AfterTonemapper 后处理材质时，它会在 Tonemapper 处理像素后调用。这意味着 PPM AfterTonemapper 将在显示像素上运行。它们不再是线性的，因为它们将输出设备编码到值中。当 OCIO 启用时，PPM 同样位于 OCIO 之后。因此，PPM 仍然对显示像素进行操作，这将是 OCIO 转换产生的显示像素。 UE 版本 - 虚幻引擎
