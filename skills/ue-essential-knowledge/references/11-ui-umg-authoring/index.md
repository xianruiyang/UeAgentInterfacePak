# UI/UMG Authoring

## 适用范围

- UMG WidgetBlueprint、HUD、菜单、卡片式界面、复杂 UI 复刻。
- UI 布局、字号、层级、裁剪、角标、按钮热区、参考图对照。
- 需要通过截图和 WidgetTree 读回共同验收的 UI 工作。

## 核心经验

1. 先定结构，再调视觉。先确认屏幕分区、功能分组、组件层级和容器关系，再调坐标、字号、颜色和装饰。
2. `CanvasPanel` 只做大区锚定。根 Canvas 负责顶栏、左区、右区、底区、浮层等一级区域；卡片内部和按钮内部不要靠 Canvas 硬摆。
3. 重要内容进入 `SafeZone`。标题、按钮、资源数值、菜单、关键状态等放在 SafeZone 内；背景、出血装饰和氛围元素可以在外。
4. 功能分区内部优先用容器。横向关系用 `HorizontalBox`，纵向关系用 `VerticalBox`，尺寸限制或尺寸边界用 `SizeBox`，整体等比缩放用 `ScaleBox`。
5. `Overlay` 只处理局部叠层。适合背景+内容+按钮热区、角标、红点、标签、遮罩和局部高亮；不用于替代整块页面布局。
6. `GridPanel` 只在横纵容器嵌套不清晰时使用。适合二维矩阵、跨行跨列和统一行列对齐；Grid cell 内的卡片仍要自己布局。
7. 内层 Canvas 是最后手段。只有布局本质是局部自由定位，且常规容器、Overlay、GridPanel 都不能表达时才使用。
8. 每个视觉元素必须有语义归属。标题、图标、角标、按钮热区应是对应组件的子节点，不能散落在父 Canvas 上靠坐标假装属于它。
9. 卡片需要区分外框层和内容裁剪层。标签、红点等出血元素放外层 Frame；卡片文字和主体内容放内部 Card，并按需要裁剪。
10. 先做平面布局，再做倾斜、透视、动画。透视应作用在整组容器上，不要逐个文字和图标手调。
11. 文字是信息层级，不是装饰。标题、微字、状态、副标题要有稳定字号、权重、位置和间距规则。
12. 图标和数字应作为组件整体处理。资源条、徽章、仪表盘、按钮图标先封成 `SizeBox/ScaleBox + Overlay` 组合，再放进父布局。
13. 对照参考图时先分析结构。先判断功能组、卡片、标签、装饰、交互入口和裁剪关系，再处理像素级相似。
14. 空间比较必须统一坐标系。截图、UMG slot、画布和局部容器不是同一层空间；比较前明确主体、原点、方向、尺寸和验收范围。
15. 验收不能只看截图。必须同时检查 WidgetTree 父子关系、容器类型、slot、裁剪层和按钮热区。
16. 局部截图要裁对真实区域。全图看整体比例，局部图看结构、对齐和层级；裁错区域会误判。
17. 多次调坐标仍不对时，优先怀疑结构。常见根因是容器选错、父子归属错、裁剪层错或组件抽象错。
18. 没有真实素材时要标明占位边界。几何色块和文字占位只能验证结构、比例、层级和交互区，不能代表最终素材质感。
19. 复杂 UI 应沉淀可复用组件。

## 推荐流程

`参考图分析 -> 空间合同 -> 一级分区 -> 分区容器 -> 组件封装 -> 组件内部布局 -> 字号/颜色/层级 -> 特殊效果 -> WidgetTree 读回 + 截图验收`
