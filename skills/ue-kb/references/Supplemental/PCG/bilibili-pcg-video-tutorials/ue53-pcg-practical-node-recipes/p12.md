# 【UE5.3 PCG教程】可编写脚本工具与PCG联动

## 知识目标

- 本集是一个很短的演示片段，主题是把 UE 的 Scriptable Tools / 编辑器工具与 PCG 工作流联动。
- 核心价值不在完整讲解 API，而在说明一种方向：把重复的 PCG 调参、刷新、批处理或资产整理动作封装成工具按钮，让编辑器内的 PCG 操作更可复用。

## 可复现主流程

- 先确定脚本工具要控制的对象：场景中的 PCG Actor、PCG Component、可暴露参数、资源引用或需要刷新的生成结果。
- 在编辑器工具或蓝图工具中选择目标 Actor，读取它身上的 PCG 组件或相关变量。
- 通过工具逻辑写入参数、切换资源、触发刷新或执行一组固定编辑器操作。
- 用一个最小场景验证工具可重复执行：同一按钮多次运行不会误选对象、不会清空无关数据，也不会让 PCG 图表进入不可恢复状态。

## 操作步骤与要点

### 用一个短片展示 Scriptable Tools 与 PCG 场景对象之间的联动思路

**内容要点：**

- 画面重点是编辑器中的工具模式和场景对象，而不是 PCG Graph 内部的完整节点链。可以把它理解为“给 PCG 制作一个编辑器侧控制面板”。
- 如果工具面向 PCG 参数，应先把可调项暴露到 Actor 或 PCG Component 上，再由工具读取选中对象并写入参数。
- 如果工具面向批处理，应限制选择范围，例如只处理带指定类、标签或组件的 Actor，避免误改整个关卡。

**参数、节点和风险点：**

## 复现检查清单

- 先在测试关卡验证工具，只处理一个明确的 PCG Actor。
- 工具入口要有选择过滤，避免误操作全场景对象。
- 写入参数后检查 PCG 结果是否刷新；如果没有刷新，确认是否需要调用组件 regenerate/update 相关操作。
- 短视频信息有限，涉及具体 Blueprint 节点、Editor Utility 或 Scriptable Tools API 时必须回看画面确认。

## 可扩展用法

- 把常用 PCG 参数做成工具面板，例如密度、随机种子、资源组、颜色或缩放范围，让关卡编辑时不用反复打开 PCG Graph。
- 把批量刷新做成安全按钮，例如只刷新当前选中的 PCG Actor，或只刷新带指定标签的对象。
- 把结果整理动作自动化，例如批量命名、移动到指定文件夹、清理旧生成结果或给生成 Actor 加标签。
- 如果后续要接入团队流程，工具应写清楚输入对象、会修改哪些属性、是否会触发重新生成，以及失败时如何回退。

## 误区与边界

- Scriptable Tools 不应该替代 PCG Graph 的核心规则。图表仍负责生成逻辑，工具只负责把重复编辑器操作封装起来。
- 不要在工具里写死某个关卡的 Actor 名称；更稳的方式是按组件、类、标签或当前选择集查找目标。
- 如果工具会批量修改资源或 Actor，建议先加 dry-run 或日志输出，确认命中的对象列表正确后再真正写入。
- 对多人项目，工具产生的结果应尽量可追溯，例如记录修改的参数、执行时间和目标对象，避免后续难以追踪 PCG 结果由谁触发。
