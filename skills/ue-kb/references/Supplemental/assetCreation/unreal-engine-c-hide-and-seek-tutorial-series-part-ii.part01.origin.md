在本教程中，我们将专门用 C++ 创建以下类： - **CPP_HealthComponent**：用于模块化和管理健康相关行为的参与者组件。 - **CPP_Interface**：具有一般游戏行为的参与者的接口。 - **CPP_Hazard**：为所有危险设置基本逻辑的父危险类。 - **CPP_SpikeHazard**：重叠时会对玩家造成伤害的儿童危险类别。 - **CPP_PoisonHazard**：儿童危险类别，重叠时会随着时间的推移对玩家造成伤害。 - **CPP_Opponent**：当玩家寻找他们时，演员会隐藏在随机位置。 - **CPP_VisionComponent**：附加到具有执行碰撞查询逻辑的角色的场景组件。 - **CPP_InteractionInterface**：可以由玩家激活的参与者的接口。 - **CPP_Switch**：将用于与阻止玩家进度的网关交互的参与者。 - **CPP_Gateway**：将与 switch 类通信以允许访问游戏中的新区域的参与者。 - **CPP_LevelScript**：用于管理全局功能和通信的级别脚本参与者。当我们创建这些类时，我们将要做的一些事情是： - 使用角色组件和场景组件来模块化功能。 - 使用接口和委托在不同对象之间进行通信。 - 从抽象基类派生子类，这些子类共享通用功能，同时又是唯一的。 - 创建动态材质实例，我们可以通过代码更改其属性。 - 利用关卡脚本参与者来促进我们世界中的对象实例之间的通信。当然，当我们将这些新类集成到我们的项目中时，对于我们在第一部分中创建的类，我们还将实现新的和改进现有的行为。但无需担心，当我们探索编辑器中的工具时，您将能够在 IDE 之外花费一些必要的时间来： - 添加自定义碰撞通道和对象类型。 - 修改和设置关卡内对象实例的属性。 - 使用目标点演员作为对手类别的隐藏位置。 - 在建模模式下创建新的网格并修改现有的网格。 - 使用建模模式的立方体网格工具勾勒出关卡的基础知识。如果以上任何或全部内容对您来说听起来不错，并且您是我从第一个教程继续学习的好朋友之一，请启动您偏好的 IDE，打开您的** CPP_Tutorial** 项目，并准备好使用 C++！对于那些喜欢正在阅读的内容、跳过第一部分，但对其所涵盖的主题感到满意的人，下一部分旨在简要地让您的项目启动并运行到可以投入其中并享受乐趣的程度！

### CPP_Tutorial：定义 PRINT 宏

在第一部分中，为了开始工作，我们在项目附带的一个源文件 **CPP_Tutorial.h** 中定义了几个我们自己的宏（如果您为项目指定了另一个名称，当然它会有所不同）。

在此头文件内部，为了基本上复制蓝图 **Print String** 节点的功能（允许您在运行时轻松地在屏幕上显示调试消息），我们创建了四个类似函数的宏，每个宏都以名称 **PRINT** 开头，以允许我们在代码中执行类似的操作。

如果您想更详细地探索这一点，我建议您查看第一个教程中的相应部分，对于那些想知道我在整个教程中谈论什么的人，每当我提到在这里或那里添加 **PRINT** 宏时，我提供了下面的代码，您可以将其添加到您自己的 **CPP_Tutorial.h** 中，或者如果您确实感到叛逆并将您的项目命名为不同的名称，则可以将其添加到您自己的 **CPP_Tutorial.h** 或任何类似的头文件中。

所有这些宏的本质是，我们调用 **GEngine** 类的 **AddOnScreenDebugMessage**，它基本上可以用于与蓝图中的 **Print String** 节点相同的目的。

为了简化生活，每当我们想在游戏过程中为自己提供调试消息时，我们将此函数合并到几个不同的宏中，根据我们感兴趣的信息的性质传递不同的参数。

我们有普通的 **PRINT** 宏，它只以白色显示一些我们传递给它的文本，**PRINT_COLOR**，它允许我们指定消息的实际颜色，**PRINT_VAR**，它允许我们查看一个或多个非布尔变量的值，以及 **PRINT_BOOL**，我们用来对单个布尔值执行相同的操作。

对于那些完成第一部分并已经定义了这些内容的人，我想指出的是，我确实对每个部分进行了微小的更改，并对 **PRINT_BOO**L 进行了一些更大幅度的调整。

这些更改可以在下面的代码中看到，我稍后会解释它们，但是很快，对于本系列的新手，您还可以看到，在这段代码中，我省略了 **PRINT** 的定义，我这样做只是因为我发现自己总是选择使用** PRINT_COLOR** 。

为了突出显示自第一部分以来我对每个宏所做的一个更改，因为调试消息对于我近中年的眼睛来说太小，我确实向 **AddOnScreenDebugMessage** 添加了一个额外的参数，这需要在此之前提供另一个参数。

在每次调用中的文本参数之后，我添加了 **true** 来为这个默认参数提供所需的值，这样我就可以更改我真正关心的默认参数，这是接下来的。

**true** 值表示较新的消息应显示在屏幕上较旧的消息之上，并且下一个参数（类型为 **FVector2D**）设置文本的比例。

正如您所看到的，对于每个函数调用，我通过传入一个 2D 向量来增加文本大小，这两个向量的值都是 1.5。

就 **PRINT_BOOL** 而言，为了简化在代码中调用它时的事情，我删除了宏的所有参数，除了 **Bool** 之外，它表示要传入的布尔变量。

我没有为消息提供特定的颜色，而是使用了条件语句，使用**三元运算符**“**？**”来声明如果布尔为真，则消息应显示为绿色，如果不是，则应显示为红色。

至于消息本身，在 **TEXT** 宏中，我使用了 **字符串化运算符**，“**#**”，它是一个 C/C++ 预处理器运算符，可将宏参数转换为字符串。

正如您在 **PRINT_BOOL** 的 **TEXT** 宏中看到的，通过添加 **#Bool " = %s"**，无论我传入的布尔变量的名称是什么，它都会转换为字符串，然后与第二个字符串连接，后者只是一个等号。

然后，%s 将根据 **Bool** 的值填充文本“true”或“false”。

如果您已完成第 I 部分，则无需进行此更改或添加参数来调整比例，只需知道对于 **PRINT_BOOL**，如果我在第二个教程的代码中的某个位置调用它并且语法对您来说看起来很奇怪，那是因为我已经更改了它。

当然，无论您是否是该系列的新手，是否真正定义这些宏和/或使用它们完全取决于您。

如果您选择这样做，请记住，无论您在项目中调用它们的什么文件，您都必须包含此头文件，在我的例子中是 **CPP_Tutorial.h**，无论您在哪里使用它们。

**CPP_Tutorial：头文件**

```cpp
CPP_Tutorial.h

// Copyright Epic Games, Inc. All Rights Reserved.

#pragma once

#include "CoreMinimal.h"

// Prints a message in a specified color for five seconds
#define PRINT_COLOR(Message, Color) if (GEngine) GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Color, TEXT(Message), true, FVector2D(1.5f, 1.5f))
```
