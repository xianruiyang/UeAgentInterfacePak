# 白盒、通行与机关空间

本页解释各制作阶段共用的尺度、表面连接、碰撞与机关空间。关卡白盒和美术白盒的职责区别，以及正式资产替换后旧替代体的去向，见[场景制作的三个阶段](scene-production-stages.md)。低成本表达仍需让地面、阻隔、入口和设施体现预期功能，复杂度低不意味着可以用不可见的补丁代替有意设计的空间。

## 尺度来自角色与玩法

各阶段的尺度设计都以功能空间的当前用途和活动容量为依据，玩家尺度、相机和动作决定需要保留的使用范围；活动或布置改变时，宽深高及其比例也要随受影响关系调整。房间、庭院、通道与机关停靠区的数值来自项目实际能力和空间意图，紧凑、压迫、开阔或宏大的空间可以采用不同尺度，不用统一米数替代设计。哪些决定由哪个阶段承担，见[阶段衔接](scene-production-stages.md#阶段衔接与回流)。

通道宽高首先受到实际碰撞形状、移动能力和镜头约束。对于常见 Character，胶囊半径与半高、`MaxStepHeight`、`WalkableFloorAngle`、跳跃、蹲伏及自定义移动都会影响结果；角色外观高度不能代替碰撞尺寸。坡度还可能受表面的 Walkable Slope Override 影响。参见 [Character Movement API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UCharacterMovementComponent) 与 [Walkable Slope](https://dev.epicgames.com/documentation/unreal-engine/walkable-slope-in-unreal-engine)。

纯粹“胶囊放得下”的尺寸未必适合转身、战斗、躲避或第三人称相机。门洞、楼梯转角和平台入口还需要容纳接近、停留、转向与离开的动作。没有一套固定门宽、层高或坡度能通用于所有角色。

设计尺寸应落到实际白盒体积，而不只是路线中心线或外轮廓。可用宽深高是扣除墙、楼板和屋顶厚度，以及必要梁柱、机关运动、设施和内容占用后剩余的空间；这些占用可以先用粗简体块表达。只用零厚度面草拟时，不能据其表面间距认定最终净空与容量已经成立。开口、楼梯坡道和机关要连同接近区、落脚面及相邻层高一起安排，不能各自放得下却接不上。

跳跃距离不是只由水平速度决定：起跳速度、重力、空中控制、起落高度、头顶障碍和落地规则都会改变可达区域。几何上的空隙与可玩的跳跃挑战应分开判断。

## 完成面与连接

地面顶面、门洞底边、台阶踏面和平台停靠面，通常比 Actor 原点更适合表达衔接关系。资产 pivot、组件相对变换、父级旋转和缩放会改变这些表面的世界位置；使用同一平移值并不能保证不同资产的表面齐平。

- 两段路面看起来接近，仍可能存在高差、细缝或碰撞凸起。需要区分几何接缝、可跨越台阶和有意设置的障碍。
- 门洞与楼梯同时需要足底空间和头顶净空；门楣、梁、坡底和上一层楼板都可能进入角色或相机的运动范围。
- 水平铺地与斜坡相交时，开口应沿实际坡面及其衔接范围组织；只按平层标高填满房间，可能把坡口盖成突出门槛。围护开口、坡侧承托和护边应使用相容的边界，保留相邻仍有效的落脚面。
- 室内壳体要考虑玩家会接近和看到的两面。反向法线、开口网格和单面渲染会产生“墙面缺失”；双面材质改变可见性，不自动补齐几何厚度或碰撞。
- 可见面共面或十分接近可能产生深度竞争；是否实际闪烁还取决于视点、深度、材质及当前几何表示。为消缝而任意叠面可能制造闪烁，不能以微移代替明确的层构造。体块在不可见内部的合理重叠与可见表面重叠不是同一个问题。

几何相交只说明表面或实体的关系。支承面与楼板底面接触、管件套接或基座嵌入可以有合理构造依据；同向重面、管路穿入通行面则需结合实际用途与可见范围判断。认可一处嵌合应限定到当前对象、接口范围和状态；尺寸、形体、安装或相邻内容改变后，不能沿用不再适用的判断。

共面交叠比例应以双方各自相关的完整表面为分母，多件覆盖同一表面时取面积并集。三角剖分片数、整件网格总面积和包围盒体积不能替代这个指标；比例也不等于错误严重性。穿交线、点接触、开口或非可靠实体没有可直接推得的体积百分比。几何诊断需说明实际分析的表示与未覆盖内容，不把源网格、碰撞代理或静态快照冒充最终渲染和动态通行结果。

这些是空间关系，不要求统一坐标表、固定生成顺序或在开搭前锁死全部尺寸。布局与建模可以互相反馈；共同基准和模块尺寸的价值在于减少接缝与修改传播成本。

## 几何表达的选择

几何表达按目标轮廓、曲率、高差与编辑边界选择。分段体块近似曲面时，分段程度需保留影响遮挡、通行和观感的形态；网格吸附用于控制构造基准，并不要求场景正交、等高。美术白盒应达到的形体与布置完成度由[阶段定义](scene-production-stages.md#形体与内容的完成程度)维护。

| 表达 | 适合的用途 | 主要取舍 |
| --- | --- | --- |
| 简单体块或模块化 Static Mesh | 独立构件、重复楼板墙体、快速替换 | 实例易调整；共享资产修改会影响其他引用，拼接和碰撞仍需合理 |
| Modeling Mode / CubeGrid | 连续体块、体积增减、切口和白盒轮廓 | 便于直接塑造空间；输出网格、材质和碰撞各有语义，不等于玩法自动完成 |
| Dynamic Mesh | 需要持续几何编辑或程序形变的对象 | 具体渲染、碰撞、持久化和运行时支持依赖组件及版本，不能照搬 Static Mesh 假设 |
| Blueprint Actor / 组件组合 | 门、升降机、交互设施与可复用构件 | 适合携带状态与行为；组件层级、运动主体和碰撞主体需要一致的含义 |
| Landscape / 大范围地形系统 | 连续自然地形 | 与多层室内、悬空楼板和洞穴空间的表达需求不同 |

UE 原生 [CubeGrid](https://dev.epicgames.com/documentation/en-us/unreal-engine/cubegrid-tool-in-unreal-engine?application_version=5.7) 用可调整的网格进行体积塑形，并支持多种输出类型。几何表达按区域编辑、复用、流送和碰撞需求选择；UE 内组织、外部部件与阶段归属统一见[阶段内容的归属与替代](scene-production-stages.md#阶段内容的归属与替代)。

## 渲染网格与碰撞是两套表示

Simple Collision 使用基本体或凸包；Complex Collision 使用三角网格。单个凸包不能保留凹洞，可能把肉眼可见的门洞、拱下或 U 形空间封住。分解凸包、独立阻挡体或适用的复杂碰撞各有成本；不是打开某个开关就统一正确。`Use Complex Collision As Simple` 下该对象本身不能进行物理模拟，不能作为所有运动或模拟对象的通用配置。参见 [Epic：Simple versus Complex Collision](https://dev.epicgames.com/documentation/en-us/unreal-engine/simple-versus-complex-collision-in-unreal-engine?application_version=5.7)。

几何形状之外，Collision Enabled、Object Type、双方 Collision Response 以及查询通道共同决定阻挡与检测。能阻挡角色不代表能阻挡相机，也不代表会生成交互所需的 Overlap 事件；Overlap 事件还要求双方启用对应事件生成。参见 [Epic：Collision Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/collision-in-unreal-engine---overview)。

导航数据描述配置代理的寻路空间，不自动等同于当前玩家实际能通过的空间；玩家能靠跳跃或电梯经过的连接，也不会仅因几何存在就自动成为 AI 可用的导航连接。

## 机关要考虑运动范围和两端使用空间

| 设施 | 需要理解的空间关系与行为 |
| --- | --- |
| 平开门 / 滑门 | 关闭体积、打开后的停放位置、运动扫过区域与通路净空；门完全打开后仍可能堵住相邻路段 |
| 楼梯 / 坡道 | 上下完成面、转折平台、头顶净空、踏步或坡面的碰撞，以及实际角色的可走条件 |
| 梯子 / 攀爬 | 两端接近与离开位置、角色姿态、镜头、进入和退出移动状态；摆出梯子模型并不自动获得攀爬能力 |
| 电梯 / 移动平台 | 停靠面、上下客区域、沿途净空、角色随平台移动的方式，以及平台不在这一层时的召回或替代通路 |

运行时需要移动的组件受 Mobility 和组件层级约束。移动可见子网格而碰撞留在原处、或只移动 Actor 却误以为所有子组件都参与相同 sweep，都可能产生不同结果。Sweep 是否检测附属组件由所用移动 API 决定，不能只看开关名称。角色站在运动基座上的行为也不同于每帧直接传送角色。

运动净空包络取实际活动组件的完整实体，包括相对偏移、厚度、附属构件与各段行程，不只取根节点轨迹或站立面。基础、铺地、围护和侧向接入口共同使用该边界，固定面与活动面按装配和通行需要衔接。不同高度可共享平面投影却需要不同开口，不能把下层通道与上层停靠处合成贯穿全高的大洞，也不能整体抬高平台掩盖重复表面。

临时禁止输入、改变移动模式或关闭碰撞的机关，需要明确正常完成和中断后如何恢复。这属于机关行为本身；状态归属和跨关卡保存见[游戏框架与状态](../10-gameplay-framework/index.md)。

编辑器中的几何与属性能说明布置和配置，实际移动、交互与镜头行为仍属于运行时结果。两者的证据范围不同；是否进行试玩由当前任务决定，不在这里附加统一测试轮次。
