### 为虚幻引擎设置渲染农场的概述

### 概述

目前虚幻引擎不提供开箱即用的渲染农场解决方案。这部分是由于农场的复杂性以及它们与工作室其他流程的集成程度。此外，虚幻引擎的实时特性还带来了一些典型渲染农场应用程序中不存在的额外挑战。 Unreal Engine 的电影渲染队列 (MRQ) 是从头开始构建的，考虑到了 Python，并尽可能多地向 Python* 公开。这意味着您可以几乎完全用 Python 创建一个集成良好的渲染农场实现，并将其连接到艺术家使用的现有 UI。

### 为什么使用自定义执行器与游戏模式进行命令行渲染？

我们最初建议以“-game”模式启动引擎，但最近改为建议启动完整编辑器并从那里运行渲染。不幸的是，ObjectId 传递基于内部“Hitproxy”传递，编辑器在视口中单击鼠标时使用该传递来确定您单击了哪个对象，因此它需要完整的编辑器。因此，它在“-game”模式下不起作用 - 作为一种解决方法，我们建议将渲染农场移至使用完整编辑器而不是 -game。这将启用对 ObjectID 通道的支持，并且您将获得与艺术家使用渲染（本地）进行的渲染更加一致的效果，因为它与他们使用用户界面时的代码路径完全相同。它会稍微增加加载时间，但可重复性（以及经过更多测试的代码路径）是值得的。本文更详细地介绍了如何在使用完整编辑器时从命令行运行渲染作业 - 一个等待资源注册表加载的 python 引导类，然后运行一个自定义执行器，根据需要操作作业，最后调用渲染（本地）使用的默认编辑器中播放执行器。 * 由于 Unreal 的 Python 集成的限制，可能需要使用 C++ 完成少量工作。

### 硬件和软件要求

渲染场通常由许多通用机器组成，这些机器可能存在于现场或异地云中。

第三方软件（例如 Deadline 或 Tractor）通常用于管理这些机器 - 它们跟踪哪些机器安装了哪些软件包/许可，并负责将作业分配到多台机器上并跟踪进度。

就这些机器的预期硬件水平而言，他们应该优先考虑高 VRAM GPU。

Unreal 没有基于 CPU 的渲染器，并且对于在多台机器上分割单个帧有很大的限制（稍后会详细介绍）。

虽然虚幻引擎 5 硬件要求页面仅列出了 64 GB 系统 RAM 和 2080 Super（8GB VRAM）（有关完整详细信息，请参阅硬件和软件规格），但列出的这些要求通常适用于针对普通消费级硬件的游戏开发人员。

在实践中，我们建议至少使用 64GB RAM，如果可能的话，使用具有 24GB VRAM 的 GPU，可能会升级到 48GB VRAM 卡。

可以使用低于此容量的卡，但您需要优化内容以实现实时使用，并在整个项目开发过程中密切关注内存使用情况。

渲染农场上的渲染并不比本地艺术家机器上的渲染占用更多内存，但通常情况下，当您提交到渲染农场时，您希望使用更多渲染通道、更高的分辨率和更多渲染功能进行渲染 - 所有这些都会占用更多的 VRAM，因此重要的是要现实地了解艺术家在本地计算机上渲染快速 1080p 渲染与在本地机器上渲染快速 1080p 渲染之间的差异。

使用光线追踪和多个模板层等在云中进行完整的 4k 渲染。

快速的多核 CPU 很重要，但不如更好的 GPU 更重要 - 特别是在高分辨率下，您更有可能受到 GPU 限制而不是 CPU 限制，因此较慢的 CPU 是更快/更多显存 GPU 的一个不错的权衡。

对于硬盘驱动器空间来说，有足够的空间来容纳您的项目及其输出非常重要，并且 SSD 很少成为该过程中的瓶颈（尽管非常慢的输出目标，例如通过网络写入远程存储设备可能会成为最慢的点。）。

一般来说，我们建议写入本地磁盘，然后将生成的文件复制到网络共享，作为单独的步骤（如果需要）。

### 一体化

总的来说，创建集成需要三个分离部分 - 您需要一种将作业提交到渲染场的方法，一种让渲染场启动正确的应用程序的方法，最后一种方法来解释来自渲染场的信息并将其转换为实际的渲染命令。前两部分将非常具体于您选择的渲染场管理软件解决方案，而第三部分则更加独立。
