# 知识的使用边界

不同材料回答不同问题：

| 材料 | 能说明什么 | 不能由它推出什么 |
| --- | --- | --- |
| 引擎机制、官方文档、源码 | 对象职责、行为与条件；具体版本的接口 | 当前项目一定使用相同配置 |
| 设计知识、案例、教程 | 可选手法、效果预期与取舍 | 所有玩家行为一致，或该案例的制作步骤是项目要求 |
| 项目规范与用户设计 | 本项目期望的玩法、约束和交付范围 | 引擎已经实现了它们 |
| 当前资产、运行状态与观察 | 已配置的内容以及观察范围内的实际行为 | 未观察到的情况也成立 |

概念问题查相关主题，版本问题查对应版本来源，现场问题查项目实际状态。不要为了一个已明确的小问题依次读完所有分类。

关卡设计中的偏好、比例、节奏和尺度都带有游戏类型、角色能力、视角及玩家目标的前提。教程中的固定轮次、检查清单和停止条件只有被当前项目明确采纳时才成为要求；历史方法论不自动覆盖当前用户目标。

本目录收录的是关键知识，不是完整引擎手册。对尚未收录的主题，可从 `ue-kb` 或 Epic 对应版本资料继续查证。社区经验与官方机制分别标注；机制事实的来源不能用来替设计偏好背书。
