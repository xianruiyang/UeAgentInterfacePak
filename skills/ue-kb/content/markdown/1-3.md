# 1.虚幻引擎程序内容优化_利用这 3 个技巧提升性能

## 知识目标

- 把本集整理为 PCG 场景的三项常用优化：Nanite 资源检查、Static Mesh Spawner 实例化数据设置、Clear PCG Link 固化生成结果。
- 明确这些优化适合大量重复实例的程序化场景，重点不是修复工程崩溃，而是降低编辑器交互和渲染阶段的负担。

## 可复现主流程

1. 在视口中切换 Nanite Visualization，先确认建筑、树木、道具和地形哪些资源没有启用 Nanite。
2. 对 PCG 会大量重复生成的 Static Mesh 批量启用 Nanite；如果版本和项目设置支持，Landscape 也需要重建 Nanite 数据。
3. 打开 PCG Graph，找到 Static Mesh Spawner，检查网格选择和实例数据设置。
4. 把 Static Mesh Spawner 的实例数据切换到更适合 PCG 大量实例的 PCG Instance Data / packed instance 方式，减少重复对象开销。
5. 最终摆放确定后，选中 PCG Component 执行 Clear PCG Link，把程序化结果固化成可独立管理的实例或 stamp。
6. 需要继续改规则时，删除固化结果，回到原 PCG Graph 重新生成，不要在固化结果上期待规则自动同步。

## 复现检查清单

- 先用 Nanite Visualization 看资源状态，再批量改资产，不要只凭口播判断。
- Static Mesh Spawner 的实例化设置要在真实 PCG Graph 中核对，避免把资源选择和实例数据设置混为一谈。
- Clear PCG Link 前先确认规则稳定；固化后再改 PCG 图不会自动影响已固化结果。
- 固化结果仍要检查材质、碰撞、LOD/Nanite 和可编辑性是否符合项目交付需求。
