## 主要更新：减少公共编辑链的重复工作

- 作者字段通过共享语法、类型和字段 codec 形成局部意图，原生操作按实际参与的属性、组件、Actor 及已知结构/引用依赖准备当前状态；不为每次局部编辑先构造完整兼容模型。
- 真实 before、最终持久 after 与实际变化继续由原 owner 采集并交给 committed 发布。观察不完整时返回 warning/pending，不把当前完整 World 减旧发布基线冒充本次变化，也不以伪造 actual 推进水位。
- 同代 model、layout、命名、rows、spans 和字节结果直接交接后续 consumer，减少重复 parse、AST 存储、重复文件读取、临时中转及与实际修改无关的桶重写。
- 稳定 ID 查找、有序 merge view 和按变化行/成员处理的 formatter，减少完整 hash map、完整 layout 及整文件内容的重复物化。未变内容只在其真实内容与来源证明成立时复用，不凭 size/mtime 相同推定安全。
- Windows 文件变化观察用于连续 UAI 服务会话中的局部来源选择；共享 NTFS 访问、文件读证明和发布复用继续保持真实字节、并发作者及原始首错语义。未实现 USN 跨重启续接。
- 无明确来源编辑的 no-op 在 native/model prepare 前短路；它不会伪造提交、推进观察不足的水位或重放旧操作。

这些优化减少不必要的捕获、序列化、解析和写入，不承诺任意资产、大图冷启动或所有操作都低于固定秒数。本次不新增统一性能基准或跨版本倍率声明；既有冷/暖、profile 和不同规模样本保持各自条件，不拼接为普遍提速结果，也没有可公布的 Token 节省比例。

## 工作区、SDK 与恢复

- 默认 export 使用 committed 模式，消费本目标、工作区和 profile 的已验证 HJSON 提交与真实联动；显式 ordinary incremental 同步独立 UE 变化，full 完整重建。三者不是可互换的重试开关。
- 新空目录默认采用当前 `/4` 发布格式。已有局部目录缺少必要 Source、行跨度、inventory、definition 或 observation 时精确报错，不再隐式重建旧完整来源。旧格式和跨服务会话的适用边界按正式导入/导出诊断处理。
- SDK 保留结构化服务端诊断、原提交 custody 及不重放恢复语义。`workspace_refresh=pending` 和 `retry_import=false` 必须与业务结果一起处理；不要只检查 `ok`。
- `operation.pending()` 是本地恢复名称 inventory，不是服务端当前运行列表。`finish()` 可推进 accepted 原操作至终态并释放；它不是仅清理状态的只读调用。普通调用继续沿原 handle，已提交动作不重新 import。

## 安装和已知边界

按 [升级说明](../UPGRADING.md) 获取固定子模块、安装 SDK 和 skills。分发包含 Plugin 源码及 Content、SDK/CLI 源码与匹配引用，不附带通用引擎 DLL 或旧独立 exe。必须按 [EnginePatches](../../UeAgentInterface/EnginePatches/README.md) 使用配套的 UE 5.6.1 并构建相关模块；本版没有改动用户项目游戏 C++ 或重新修改引擎。
