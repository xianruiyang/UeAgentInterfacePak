## HJSON 编辑与性能

- 公共 workspace owner 复用已验证的输入解析与语义结果，增量合成 model/layout，减少重复格式化、完整副本和发布写入。机器基线与 inventory 使用内部紧凑存储；HJSON 仍是用户编辑入口，不能手工修改机器状态。
- 复用依据包含真实内容验证与版本/结构绑定，不以文件时间相同推定内容未变。独立持久读回、实际变化发现、事务与错误诊断继续保留。
- Level 对可证明安全的普通原生属性复用状态；结构、引用、未知联动等不满足条件时扩大范围或走完整路径。其他资产共享公共机制，但不因此承诺所有领域都支持局部捕获。
- `scene_editing` 在既有变换/材质等能力上，支持精确类型筛选的原生灯光强度、局部光衰减半径及 PostProcessVolume `Settings`；未编辑成员和覆盖标志保持。完整属性 profile 仍兼容，碰撞等未投影字段继续使用完整属性路径。
- 同输入完整 profile 的一次对照，import 内部总耗时由 323.73 秒降至 171.28 秒。最终同一 build 的完整 profile 冷/暖样本为 171.28/110.23 秒，`scene_editing` 为 45.50/38.74 秒。后两组是 **profile 选择差异**，不能当作同 profile 优化倍率；这些数值不包含前置 export，也不保证其他资产或机器达到相同耗时。

正式能力与限制见 [HJSON 公共导入](../../UeAgentInterface/docs/active/t09_hjson_import_core.md) 和
[Level 文档](../../UeAgentInterfaceCMD/docs/active/t26_level_world_domain.md)。Agent 继续使用普通 export → 编辑 HJSON → import，不需要手工维护增量依赖或增加一组命令。

## 截图默认策略与后台零尺寸

`capture.image.execute` 的 `policy_id` 现在可以省略，由公共策略 owner 依据 subject 选择：

| subject | 省略时的策略与边界 |
| --- | --- |
| `capture-subject:viewport:active` | `policy:image-capture:viewport/v1`，当前 Level 原生视口 |
| `capture-subject:asset:<object-path>` | `policy:image-capture:asset-preview/v1`，由已有资产预览 owner 判断实际类型与 target 是否支持 |
| Actor 或其他无法确定观察职责的身份 | 返回明确诊断，要求显式策略 |

资产身份不代表任意资产都能 3D 预览；地图资产不会偷偷切换当前关卡。明确的序列相机/时间任务继续使用显式序列策略。

```python
# 默认 Level 原生截图；parameters 仍必填。
result = client.capture.image_execute(
    "capture-subject:viewport:active", parameters={"format": "png"}
)
# 原来的三个位置参数调用继续有效；显式合法 policy 优先。
result = client.capture.image_execute(
    "capture-subject:viewport:active",
    "policy:image-capture:viewport/v1",
    {"format": "png"},
)
```

空值、空白、未知策略和不支持目标不会被吞作默认，也不会自动换成另一种渲染。
非零 Level 原生默认保持当前相机、曝光、show flags 与 Game View；回执记录实际 `policy_id`、`policy_defaulted`、渲染来源及显示状态。

后台原生尺寸为零时，Level 单图与已接入的原生资产预览自动按窗口所属单显示器工作区初始化**同一个原生 viewport**，不切换 SceneCapture，不激活或最大化窗口。
显式合法尺寸按既有合同优先；显示信息不可用时依次使用主显示器、1280×720，自动尺寸等比限制最长边 4096，不使用多显示器虚拟桌面总宽。
回执的 `capture.viewport_initialization` 说明零尺寸原因、尺寸来源、实际尺寸及固定尺寸状态恢复。
该过程会推进真实渲染历史，不承诺与任意时刻前台逐像素一致；其他失败及未接入策略仍保留原诊断。

日常场景、场景内材质和灯光评价使用原生视口；独立序列渲染保留其用途与来源标记。
早期 sequence/native 的亮度差异不等于本版已解决所有曝光差异。完整参数见
[Capture Media 文档](../../UeAgentInterfaceCMD/docs/active/t44_capture_media_operation.md)。

## 同版交付的其他内容

- Fab 的正式发现、查询、下载/导入与恢复流程及 type/style 查询说明；本地 downloads/files 查询不再排在网络队列后。沿用原生登录，不新增购买、授权领取或代签协议行为。

- skills 更新场景制作、原生截图、照明与曝光、资产替换和空间判断说明；摆放辅助显示与正式灯光评价不再混用。
