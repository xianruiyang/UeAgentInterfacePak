# 阅读总则

## 用途

本目录用于帮助 Codex 在面对 UE 任务时选择合适的知识分类。它不是完整知识正文，而是阅读顺序和判断规则。

## 先判断任务类型

- 概念解释：先读核心概念，再读对应系统分类。
- 实际制作：先读对应系统分类，再结合 UAI authoring 工作流。
- Bug 排查：先读对应系统分类，再读性能、调试与验证。
- 代码/API 实现：先读 C++、插件与 API，再回到本地 UE 源码确认。
- 当前项目状态：先用 UAI 或本地文件读回，知识文件只能提供背景。
- UI/UMG 布局、复刻或视觉排版：先读 UI/UMG authoring，再结合空间合同和 UAI authoring 工作流。

## 阅读顺序

1. 明确主体：资产、节点、模块、组件、Actor、材质、系统或插件。
2. 明确上下文：编辑器状态、运行时状态、保存状态、导出 JSON、源码实现或截图观察。
3. 选择最小相关分类。
4. 对版本敏感信息做本地确认。
5. 输出时区分“通用 UE 知识”和“当前项目事实”。
